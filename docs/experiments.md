### Детали оптимизаций (строка 6)

**Префетч (`prefetch_factor=8`)**

`PrefetchDatasetLoader` оборачивает `CsvAudioDatasetLoader` и загружает аудиофайлы в фоне через `ThreadPoolExecutor` с 8 воркерами. Используется скользящее окно из 8 `Future`-объектов: пока GPU обрабатывает текущий батч, следующие 8 файлов уже читаются с диска параллельно. Порядок результатов сохраняется.

**Компиляция модели (`torch.compile`)**

```python
torch.compile(model, backend="inductor", mode="reduce-overhead")
```

- `backend="inductor"` — PyTorch 2.x backend, генерирует оптимизированный Triton/CUDA-код
- `mode="reduce-overhead"` — захватывает CUDA graphs, минимизирует Python overhead на каждый forward pass
- Прогрев: 3 dummy forward pass в `__post_init__` — компиляция происходит до старта таймера инференса
- Дополнительно: `torch.autocast(dtype=float16)` (mixed precision) + `torch.no_grad()`

**⚠️ Баг: `vad_time_s` потеряно в строке 6**

`build_timing()` ищет `vad_time_s` через `getattr(dataset, "loader")`, но при `prefetch_factor > 0` `dataset` — это `PrefetchDatasetLoader`, у которого нет атрибута `.loader` (он спрятан в `.inner.loader`). Из-за этого `vad_time_s` не попало в `timing.json`. Реально VAD работал — время просто не было записано.
