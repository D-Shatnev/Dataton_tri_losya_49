## Indexers

Индексатор отвечает за построение индекса эмбеддингов и поиск ближайших соседей для каждого объекта.

В нашем пайплайне энкодер строит эмбеддинги, а индексатор принимает матрицу эмбеддингов и возвращает
матрицу индексов `top-k` ближайших соседей для каждого объекта (без self-index).

### FaissInnerProductIndexer (faiss_ip.py)

Файл содержит реализацию KNN-поиска на основе `faiss.IndexFlatIP` с косинусным сходством:

- перед добавлением в индекс все эмбеддинги L2-нормализуются, что превращает inner product в косинусное сходство;
- поиск выполняется с `topk + 1` соседями, после чего self-index (объект сам себе сосед) сдвигается в конец и исключается из результата;
- индексатор stateless: каждый вызов `neighbors` строит новый FAISS-индекс с нуля, что упрощает API и гарантирует воспроизводимость.

API:

- `FaissInnerProductIndexer.neighbors(embeddings, topk) -> np.ndarray` — возвращает int64-массив формы `[N, topk]`.

Вспомогательная функция:

- `_l2_normalize_rows(x, eps)` — нормализует строки матрицы к единичной L2-норме.

### FaissASNormIndexer (faiss_as_norm.py)

Реализация KNN-поиска с **Adaptive Score Normalization (AS-Norm)**. AS-Norm калибрует косинусные скоры
относительно фоновой когорты (imposter cohort), устраняя индивидуальное смещение скоров дикторов.

#### Алгоритм

1. L2-нормализация всех эмбеддингов.
2. Случайная выборка `cohort_size` эмбеддингов из датасета (seed = `cohort_seed`).
3. Вычисление матрицы скоров `[N, cohort_size]` = `emb @ cohort.T`.
4. Для каждого запроса `i`: топ-`top_n` скоров из когорты → `μ_q`, `σ_q`.
5. Для каждого кандидата `j`: топ-`top_n` скоров из когорты → `μ_e`, `σ_e`.
6. AS-Norm формула: `s_norm = 0.5 * ((s - μ_q)/σ_q + (s - μ_e)/σ_e)`.
7. Поиск топ-k соседей по нормализованным скорам через `np.argpartition`.

#### Параметры

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `cohort_size` | int | 1000 | Размер случайной когорты. Рекомендуется 500–2000. При 1000 и N=134 698 пиковое потребление RAM ~1.1 ГБ. |
| `top_n` | int | 200 | Топ-N скоров из когорты для вычисления μ и σ. Должен быть ≤ `cohort_size`. Рекомендуется ~20% от `cohort_size`. |
| `cohort_seed` | int | 42 | Seed для воспроизводимой выборки когорты. |

#### Потребление памяти (RAM)

Всё вычисление выполняется на CPU (numpy). GPU не используется.

Пиковое потребление определяется матрицей скоров `[N, cohort_size]` float32:

```
RAM ≈ N × cohort_size × 4 байт
```

При N = 134 698, cohort_size = 1000: **~515 МБ** (пиковое ~1.1 ГБ с учётом нормализованной матрицы).

#### Детерминизм

При фиксированном `cohort_seed` результаты полностью воспроизводимы между запусками.

#### TOML-конфиг

```toml
[index]
backend      = "faiss_as_norm"
topk         = 10
cohort_size  = 1000
top_n        = 200
cohort_seed  = 42
```

### Как добавить новый индексатор

1) Создайте новый файл в этом каталоге (например `annoy_indexer.py`, `hnsw_indexer.py`).
2) Реализуйте интерфейс `Indexer` из `src/dataton_tri_losya_49/pipeline/interfaces.py`:
   метод `neighbors(embeddings, topk) -> np.ndarray` должен возвращать int64-массив формы `[N, topk]` без self-index.
3) Экспортируйте класс в `indexers/__init__.py`.
4) Добавьте ветку в `build_indexer()` в `pipeline/registry.py`.
5) При необходимости добавьте новые параметры в `IndexSection` в `pipeline/config.py` и их парсинг в `load_experiment_config()` / `load_inference_config()`.
