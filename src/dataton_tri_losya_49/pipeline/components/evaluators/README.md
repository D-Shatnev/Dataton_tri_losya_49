## Evaluators

Evaluator отвечает за вычисление метрик качества по результатам retrieval-задачи.

В нашем пайплайне энкодер строит эмбеддинги, индексер возвращает `top-k` соседей для каждого объекта,
а evaluator превращает это в числовые метрики (для dev-флоу, когда есть `speaker_id`).

### Precision@K (precision_at_k.py)

Файл содержит реализацию метрики Precision@K для KNN retrieval:

- на вход подаётся матрица индексов соседей формы `[N, M]`;
- на вход подаётся вектор меток `labels` формы `[N]` (speaker id после маппинга в int);
- на выходе получаем словарь вида `{ "precision@1": ..., "precision@5": ... }`.

Baseline-style обработка self-index:

- в выдаче соседей может встречаться self-index (объект сам себе сосед), особенно если поиск делался по тому же набору;
- self-index (если найден) сдвигается в конец строки и исключается из первых K;
- если вы передали ровно `k_max` соседей и среди них есть self-index, метрика становится неоднозначной —
  в этом случае код выбрасывает ошибку и просит передать `k_max + 1` соседей.

API:

- `precision_at_k_from_indices(indices, labels, ks) -> dict[str, float]` — функциональная версия.
- `PrecisionAtKEvaluator.evaluate(neighbors, labels, ks)` — адаптер под интерфейсы пайплайна.

### Как добавить новый evaluator

1) Создайте новый файл в этом каталоге.
2) Реализуйте интерфейс `Evaluator` из `src/dataton_tri_losya_49/pipeline/interfaces.py`.
3) Подключите его в фабрике/runner.
